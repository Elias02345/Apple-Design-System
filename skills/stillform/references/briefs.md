# Forward-test briefs

Use a fresh brief to check whether the skill works beyond the gallery. Give the implementer the brief and skill. Keep the evaluation prompts for a separate reviewer or a second pass on the runnable result.

### Repair appointment

A tenant can choose a repair window, add a note, and reschedule. The connection sometimes drops after submission. Use the existing product's type and colors. Keep the appointment usable with one hand and large text.

**Evaluate:** Can the tenant tell whether the appointment was booked? Does retry duplicate the booking? Does an offline failure retain the note and chosen window? Does a person who declines reminders still finish? Is the appointment time unambiguous in the person's time zone?

### Audio editor

A keyboard user trims a clip, compares the edit to the original, and exports. On a small screen, preserve precise adjustment.

**Evaluate:** Can someone perform the trim without dragging? Does the waveform have a numeric equivalent? Does cancelling export leave the edit intact? Does reduced motion preserve playback position? Does a screen reader encounter meaningful controls in order?

### Museum collection

A visitor compares specimens while a curator records field notes. Visitors should see the object and its identity immediately. The curator needs durable notes and filter continuity.

**Evaluate:** Can visitors compare without opening every item? After an item disappears from a filter, where does focus go? Is note storage described accurately when persistence fails? Does real imagery remain legible in both appearances?

### Spatial reading desk

A reader opens two documents in a shared space, compares passages, and returns to the original place. Use standard windows unless the task justifies another presentation.

**Evaluate:** Can a person select the intended target without precision pointing? Does changing window size preserve the passage? Can the same action be performed without an elaborate gesture? Which claims require a headset to verify?
